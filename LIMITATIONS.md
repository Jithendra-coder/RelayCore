# Current limitations

RelayCore is an actively developed prototype. It is not a production workflow product yet.

- OIDC and workspace code is locally tested, but no live identity-provider flow was verified. Email invitations, MFA, recovery, and user account administration are missing.
- GitHub App workspace linking and signed pull-request webhooks, plus Slack OAuth, signed `app_mention` events, and a bounded message action, are implemented and locally tested with mocked provider responses; no live provider credentials are configured. Only GitHub `opened`, `reopened`, `synchronize`, and `closed` pull-request actions and Slack `app_mention` events are normalized. GitHub API actions and provider-side GitHub uninstall are missing. Slack posting accepts only a conversation ID and static text; delivery is at least once and can duplicate if a successful post's response is lost. Production custom and provider webhooks can trigger exact `type` matches to versioned HTTP or Slack message workflows. JSON Pointer references in the HTTP JSON body can read from the accepted event; URLs, headers, Slack message text, and response-to-next-step mapping are static. The encrypted HTTP bearer credential is bound to one exact operator-allowlisted hostname.
- Custom webhook signing secrets and workspace bearer credentials are Fernet-encrypted with a required environment-injected key. Key versioning and automated master-key rotation are absent; provider-side token revocation is not implemented.
- Production workflow definitions support constrained HTTP and Slack message actions, with manual starts, exact custom-webhook triggers, or durable interval schedules. Schedules run the current published version, use bounded tenant queue admission, and can be paused/resumed/cancelled. They do not support cron or timezone calendars, and schedule management is API-only; a version requiring webhook event data pauses its schedule. Conditional branches, waits, approvals, response mapping, and compensation are missing. Demo Mode has a separate sandbox action allow-list.
- PostgreSQL is the durable queue. It is sufficient for the measured local workload, but independent broker replay/consumer scaling has not been tested. The per-tenant event-ordering lock can become a write bottleneck.
- Logical PostgreSQL backup and restore helpers exist. The archive was generated and validated locally, but a successful restore into a disposable database and managed backup retention are still unverified.
- The default local stack embeds workers under the API supervisor. A separate worker role is available through `python -m app.worker` and `compose.workers.yaml`; the process boundary is locally tested but has not been exercised in staging. Worker IDs must be unique across deployment hosts.
- Real-time progress uses polling-backed SSE over PostgreSQL. There is no independent real-time gateway or durable notification outbox.
- HTTP actions use a 1-second maximum socket/read timeout and 64 KiB response cap; the resolver itself uses the host OS resolver and may outlast the task lease if infrastructure DNS stalls. In-flight requests can finish after cancellation; HTTP providers must honor the supplied idempotency key, while Slack posts may duplicate after an ambiguous result. Raw webhook bodies and parsed JSON expire on a configurable schedule, but event metadata and dedupe keys remain indefinitely; database backups and WAL may retain pre-expiry copies. Per-endpoint JSON schemas are absent. Apply edge network limits before exposing public ingress broadly.
- Metrics are limited to tenant-scoped Prometheus values and dashboard aggregates. OpenTelemetry traces, pool metrics, Grafana dashboards, alert rules, and provider metrics are absent.
- CI runs Ruff, pre-commit, tests with coverage reporting, and a weekly Python dependency audit. Type checking, coverage thresholds, container OS/image vulnerability scanning, staging, deployment rollback, and cloud production are not implemented.
- The SDK, CLI, complete product UI, final evidence pack, case study, and demo video are not implemented.
- Current load and query numbers are local synthetic evidence only. See [BENCHMARKS.md](BENCHMARKS.md).
